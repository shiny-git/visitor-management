# visitor_management
# Visitor Management Application

A Flutter-based Visitor Management Application designed for front-desk and security personnel of a real estate organization.

The application allows staff to register visitors, manage visitor records, generate and scan QR codes, and record visitor check-in and check-out activities.

The application uses a persistent Mock REST API for storing visitor records. No separate backend project is required.

## Project Overview

The Visitor Management Application provides a simple interface for managing customer, vendor, and other visitor activities across residential projects.

### Main Objectives

- Register new visitors
- View and manage existing visitor records
- Search visitors by name or mobile number
- Generate a unique QR code for each visitor
- Scan visitor QR codes
- Retrieve visitor information using the visitor ID
- Check visitors in
- Check visitors out
- Display visitor activity statistics
- Maintain visitor data using a persistent REST API

# State Management

## Provider

The application uses the `Provider` package with `ChangeNotifier`.

The main state-management class is:

VisitorProvider

It manages:

- Visitor records
- API loading state
- API errors
- Registration
- Editing
- Deletion
- Search
- Check-in
- Check-out
- Dashboard statistics

### Provider flow


Screen
  ↓
context.read<VisitorProvider>()
  ↓
VisitorProvider
  ↓
VisitorApiService
  ↓
MockAPI


After an API operation succeeds, the Provider updates the local visitor list and calls:
notifyListeners();


This causes all relevant screens to rebuild automatically.

This avoids restarting the application to see updated visitor information.

The application uses MockAPI as the persistent REST API.

#  API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/visitors` | Retrieve all visitors |
| GET | `/visitors/{id}` | Retrieve a specific visitor |
| POST | `/visitors` | Register a visitor |
| PUT | `/visitors/{id}` | Edit visitor information |
| PATCH | `/visitors/{id}` | Update status/timestamps |
| DELETE | `/visitors/{id}` | Delete visitor |

#  Visitor Data Model

Each visitor record contains:

```json
{
  "id": "1",
  "name": "Rahul Sharma",
  "mobile": "9876543210",
  "email": "rahul@example.com",
  "visitor_type": "Customer",
  "project": "Project A",
  "purpose": "Site Visit",
  "status": "Registered",
  "created_at": "2026-10-28T10:00:00+05:30",
  "check_in_time": null,
  "check_out_time": null
}
```

### Fields

| Field | Description |
|---|---|
| `id` | Unique visitor ID generated by MockAPI |
| `name` | Visitor name |
| `mobile` | 10-digit mobile number |
| `email` | Optional email address |
| `visitor_type` | Customer, Vendor, or Other |
| `project` | Project A, Project B, or Project C |
| `purpose` | Purpose of visit |
| `status` | Registered, Checked In, or Checked Out |
| `created_at` | Visitor registration timestamp |
| `check_in_time` | Check-in timestamp |
| `check_out_time` | Check-out timestamp |


MockAPI generates the unique `id` for each record.

#  Application Features

## Dashboard

The dashboard displays:

- Total Visitors Today
- Currently Checked In
- Checked Out Today

It also provides shortcuts to:

- Register Visitor
- Scan QR Code

Dashboard statistics are calculated from visitor records retrieved through the API.


## Visitor Registration

The registration form contains:

- Visitor Name
- Mobile Number
- Email
- Visitor Type
- Project
- Purpose of Visit

Validation includes:

- Required visitor name
- Exactly 10 digits for mobile number
- Optional email validation
- Required purpose

New visitors are assigned:

```text
status = Registered
```

After successful registration, the API-generated visitor ID is used to generate the QR code.

---

## Visitor List

The visitor list provides:

- Visitor name
- Mobile number
- Project
- Visitor type
- Current status
- Search
- View details
- Edit
- Delete

Search can be performed using:

- Visitor name
- Mobile number

---

## Visitor Details

The visitor details screen displays:

- Visitor information
- Current status
- Visitor ID
- QR code
- Registration timestamp
- Check-in timestamp
- Check-out timestamp

Available actions depend on the visitor status.

---

## QR Code Generation

Each registered visitor receives a QR code containing the unique visitor ID.


## QR Code Scanning

The QR scanner:

1. Opens the device camera
2. Scans the QR code
3. Extracts the visitor ID
4. Retrieves visitor information from the API
5. Displays visitor details
6. Allows check-in or check-out according to the current status


#  Known Limitations

- MockAPI is used instead of a production backend.
- Authentication and user roles are not implemented.
- One visit session per visitor registration is supported.
- The application requires an internet connection for API operations.
- QR scanning requires camera permission.
- Dashboard statistics depend on the visitor records available through the MockAPI service.
- MockAPI availability is required during evaluation.
- Advanced tablet-specific layouts are not implemented.
